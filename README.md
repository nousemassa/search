# Проект `search` — свой инстанс поиска и своя MCP-обёртка

**Что это.** Инстанс **SearXNG** (`127.0.0.1:8090` наружу, `searxng:8080` внутри сети) и **MCP-обёртка**
`mcp-searxng` (`127.0.0.1:3001` наружу, `mcp-searxng:3000` внутри сети), которая превращает JSON-API поиска
в MCP-инструменты: `searxng_web_search`, `searxng_search_suggestions`, `searxng_instance_info`,
`web_url_read`.

**Почему отдельный проект.** Поиск — служба общего назначения: политику движков, таймауты и лимиты
MCP-сессий задаём мы, а не тот, кто его запускает. Своя папка, свой композ и своё имя проекта дают
отдельную единицу управления (метки, пересоздание, откат) и не связывают поиск с жизненным циклом
любого продукта.

**Почему свой инстанс.** Политику движков, таймауты и лимиты MCP-сессий задаём мы: набор движков
зафиксирован в `searxng/settings.yml`, лимиты обёртки — осознанные (см. «Настройки»).

## Как запускать

```bash
cp .env.example .env   # заполнить SEARXNG_SECRET и PLATFORM_NETWORK
make up                # поднять оба сервиса и проверить их (JSON-поиск + /health обёртки)
make status            # только проверка
make stop              # остановить
make check             # офлайн: композ разбирается, настройки инстанса корректны
```

## Контракт с остальными

* **Сеть — общая с платформой** (`external: true`, имя в `PLATFORM_NETWORK`): создаёт её стек платформы,
  проект её не создаёт.
* **`mcp-searxng:3000` — контракт в сети**: имя службы и порт менять нельзя — к ним приходят по имени.
  `searxng:8080` — контракт внутри проекта: обёртка ходит туда.
* **Порты наружу — только `127.0.0.1`**: они нужны для хостовых проверок и ручных проб, а внутри сети
  служба доступна по имени.
* **Том кеша назван явно** (`search-cache`): объявленный без `name:` том получил бы префикс проекта, и
  смена имени создала бы новый пустой том, а старый остался бы висеть. Состояние здесь — только кеш.

## Настройки

* `searxng/settings.yml` — политика движков (`keep_only`) и JSON-формат. Монтируется **одним файлом**:
  политику правит репозиторий, а не том, оставшийся от прежнего запуска. Пропадёт строка
  `disabled: false` у движка — он молча исчезнет из выдачи, поэтому набор проверяется `make check`.
* Лимиты обёртки (`MCP_RATE_*`) выше дефолтных: клиент держит одну сессию на выпуск и допускает
  параллельные прогоны; упираться в собственную защиту — не то, ради чего она ставится.
* Кеш поиска (`SEARCH_CACHE_*`) снимает повторные запросы к внешним движкам.

## Окружение

Значения читаются из `.env` рядом с композом (образец — `.env.example`), файл обязателен.
`SEARXNG_SECRET` перекрывает `server.secret_key` из `settings.yml`. Лончер ОТКАЗЫВАЕТСЯ стартовать без
непустого секрета: иначе он молча откатился бы к умолчанию, то есть настройка безопасности изменилась бы
без единой строки в журнале. Общий `.env` воркспейса, если проект стоит внутри воркспейса, подключается
как основа и только для подстановок.

## Чего в проекте намеренно нет

* **Сторожей и таймеров** — наблюдение живёт в обвязке воркспейса и находит контейнер по метке проекта;
  этого репозитория оно не касается.
* **Своего кода** — службы чужие, наши здесь только композ, настройки инстанса и лончер.
* **`--remove-orphans`** — запрещён: он удаляет контейнеры, которых нет в ЭТОМ файле.
